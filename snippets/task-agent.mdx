### Task Agent changes with staff review

The **LibOps Task Agent** does the technical work. Your team reviews every change:

*   **Site managers** start from plain text in the Dashboard or Slack.
*   **The Task Agent** implements the change on a task branch and deploys it to an isolated preview environment.
*   **Engineers** review the diff in a standard GitHub pull request, including code, configuration, and dependencies.
*   **Site managers** validate the live preview before the change merges to production.

Every change is transparent, reviewable, and tied to the GitHub workflow your team already knows.

Task Agent is currently managed beta, not generally available. The candidate production catalog has one runtime selection: the `codex` harness through an exact `libops/cli-sandbox` digest, using the customer model name `glm-5.2:cloud`. The hosted controller owns the direct sandbox launch and does not trust customer Compose configuration to define it. The private Cloud Run service in the customer organization is an authenticated gateway, not a model host: inference runs on Ollama Cloud after the gateway maps `glm-5.2:cloud` to `glm-5.2`. LibOps enables a release only after its pinned sandbox and embedded skills pass verification, gateway readiness succeeds, and an end-to-end coding canary passes.
